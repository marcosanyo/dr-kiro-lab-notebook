# Exit code 127 without the solver (reproduction)

Script: `spikes/timing/env_127.py`. Machine: the builder's Mac, Docker Desktop, image `opencfd/openfoam-default@sha256:1ba02114…`
(from `model/image-lock.toml`). Each iteration writes a case folder with `render_case` under
`bench-run/wind-tunnel/env-127/<pattern>/`, starts one container with the options of `DockerRunner.command`
(`--rm --name --user <uid>:<gid> -v <case>:/case <image@digest>`; the runner has no `-w`) with a short command
instead of `/case/Allrun`, then moves the folder as the pattern says. No solver runs. Nothing is retried. The
numbers below are copied from the script's output files (`bench-run/wind-tunnel/env-127-*.txt`, git-ignored).

## Patterns

- `driver`: one fixed folder name; after each container the folder is renamed to `random-kept-NNN-drawI` (the
  rename of the measurement driver), and the same name is created again at once.
- `trash-new`: the production pattern. A new name per iteration (`FIXED_SEED + i`, as the bench gives a different
  trial seed to every trial); the previous folder is moved to `trash/` with `move_to_trash` before the next is made.
- `trash-same`: one fixed name; after each container the folder is moved to `trash/` and `trash/` is deleted, then
  the same name is created again at once (what `run_trial` does when two trials get one seed).

## Results

| pattern | command in the container | iterations | failures | machine time |

| `driver` | `test -x /case/Allrun && ls /case` | 1000 | 0 | 296.1 s |
| `trash-new` | `test -x /case/Allrun && ls /case` | 1000 | 0 | 300.6 s |

(Three-iteration smoke runs of each pattern before these gave 0 failures; they are not counted. A second 1000-iteration
`driver` pass was started by mistake and stopped before it ended; it is not counted.)

Failing output, `trash-same`, first run (all 84 alike): exit code 1, empty stdout, empty stderr, 0.24 to 0.28 s, and
`Allrun` present on the host. Second run (all 10 alike): exit code 1, 0.23 to 0.30 s, stderr
`ls: cannot access '/case': No such file or directory`, `Allrun` present on the host. With the runner's own command
`/case/Allrun` this is exit code 127 and `/case/Allrun: No such file or directory`, as in the 5 faults of
`random-points.md`.

Failing iterations of the first `trash-same` run: 84 of 1000, no failure in the first 4 iterations; the gap between two
failures was between 1 and 56 iterations. 35 of the 84 fall on a multiple of 5 (17 would be expected by chance); this is
noted, not explained.

## Reading

- The fault is that the container does not see the bind-mounted folder at all (`/case` is absent in the container),
  while the folder is complete on the host. It appears when a folder name is created again right after a folder of
  that name was moved away and deleted (`trash-same`). The most likely reason is a cached view of that path in the
  Docker file sharing; that is a guess, not a finding.
- It did not appear in 1000 iterations with a new name each time (`trash-new`, the production pattern) and not in 1000
  iterations of `driver`, where the old folder is renamed aside and the name is created again at once but the old folder
  is kept, not deleted.
- It was not reproduced in the way of the five original faults (a failed run's folder renamed aside, then a run of about
  55 s). The original runs are 55 s apart, the loop 0.3 s; whether a longer gap changes the fault was not tested.
