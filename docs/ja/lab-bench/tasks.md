# タスク: lab-bench

まずコアのタスク（要件 1-16、設計のセクション 1-13）、次にフロントエンドのタスク（要件 17、設計の「Front end」パート、
タスク 17-21）です。各タスクは、そのテストが通り、`uv run ruff check` と `uv run ruff format --check` がクリーンな状態で
終わります。テストはフェイクアプリケーションか小さな手作りのフィクスチャだけを使います。`bench/` 内のコードやテストは
`body-lab/model/` を読みません。

**Stop and ask（止めて確認）** の付いたタスクはユーザーへの報告で終わり、次のタスクはその回答を待ちます。

## フロントエンド（要件 17）

これらのタスクは、完了済みのタスク 13-16 の後に続きます。設計 F12 の決定は承認済みです。フロントエンドは MCP SDK を
import する唯一の場所です。

- **17. MCP サーバー、レンダリング、キュー** — 未着手
  - D1 で承認された固定バージョンの `mcp` を持つオプション依存グループ `frontend` を追加する。import 禁止ルールを広げ、
    `bench.core` が `mcp` を import できないようにする。`uv.lock` をコミットする。
  - `config.py`（セッション設定ファイル。デフォルト値なし、`resume` は必須）、`describe.py`（宣言から作る説明。起動時に
    builder レベルでスキャンする）、`render.py`、4 つのツールとワーカースレッドでのコア呼び出しを囲む公平なロックを持つ
    `server.py`（設計 F3、F4、F6、F7）。コンソールスクリプト `bench-mcp`。
  - `config.py` は `SessionConfig` の各フィールドに 1 つずつのフィールドと、`resume` を読む（設計 F7、D8）。
  - `render.py` は、未計測結果を `not_measured` に分け、画像をパスにして `RunResult` を表示し、`Accepted` を
    `{"budget_remaining": n}` として表示する（設計 F4）。task 18 を超えてコアの変更が必要なら、止めて確認する。
  - フェイクアプリケーションを使い、SDK のインプロセスクライアントを通したテスト: 4 つのツールが一覧に出て、`start` と
    `stop` は出ない。拒否はコアのテキストを持つツールエラーになる。ベンチ障害はツールエラーになり、その後の呼び出しは
    拒否される。並行した 2 つの `run_experiment` 呼び出しは `Ran` を 1 つと `Refused` を 1 つ返す。セッション設定の
    変数がなければサーバーは停止する。
  - _要件: 17.1-17.5, 17.17, 17.19, 17.20_
