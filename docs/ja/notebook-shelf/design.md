# Design: notebook-shelf
この設計は `notebook-shelf` の要件 1〜7 を対象とします。`lab-notebook` のページの層を変え、その下はそのまま残します。
どの Kiro か: すべて **ビルダー** が作って動かし、**訪問者** が読みます。
## Overview
ビルドの 4 つの段階は変えません。段階 1 は記録、choices のファイル（`choices.py`）、cover のファイル、`--display` が与えられたときは表示用のマニフェスト（`display.py`）を読みます。段階 3 は 3 種類のページを作ります: 棚のページ（`pages/shelf.py` と `pages/book.py`）、インクの凡例（`pages/legend.py`）、「ラボのしくみ」（`pages/how.py`）。なくしたもの: 表紙、ラボ、セッション、リプレイ、バンドのページと、`chart.py`、`bands.py`、`plots.py`。
## Pages
- セッションごとに 1 ページ `<application>-<session>.html` と、`cover.toml` が最初のラボについて指すセッションのページである `index.html`。この 2 つは同じバイト列です。
- どのページも、見出し、ラボの札（各ラボが開くセッションへのリンク）、開いているラボのカード（リンク）、開いたノート（`article.book`）を持ちます。
- ページ内の id: 規則のカードに `row-<id>`、仮説の行に `H<n>`、実験に `E<n>`、試行のカードに `E<n>-T<n>`、予測に `H<n>.P<n>`。閉じたメモの中の id へのリンクは、そのメモを開きます（`notebook.js`）。
## Choice files（要件 2.3）
`choices/<application>/<session>.toml`: `title`、`subtitle`、`summary`、`line`、`model`、`date`（YYYY-MM-DD）、`color`（6 つの帯の色のどれか）、`[progress]`（`measurement`、`better`、任意で `equals` つきの `require`）、`[[polaroid]]` を 2 つ（`heading`、`trial`、`words`、任意で `star`）。試行が 1 つのセッションは写真 1 枚、0 のセッションは写真も `[progress]` も要りません。`choices/cover.toml`: アプリケーションごとに `[[lab]]` を 1 つ、`application`、`case`、`about`、`open`、`unit`。どの文にも長さの上限があります。`model` と `date` は記録にないので、人が書きます。`<fill in>` のモデルは書かれたまま出ます。
## 「ここまでの一番」（要件 3.3）
`progress.series` は試行を順に見ます。測定が数で、`require` があれば 2 つ目の測定が `equals` に等しいとき、その試行は数えられます。数えられた値がそれまでの一番より良ければ一番が動きます。最初に数えられた試行が線を始め、「new best」にはなりません。段は、変化が一番低い値と高い値の幅の 4% 以上のときに名前がつきます。グラフはインライン SVG で、文字は鉛筆のセグメントと手書き風のラベルです。記録にない数字はありません。
## 予測の当たり
ベンチが記録したすべての結果（hit、miss、not-checkable）のうちの hit。一度も走らなかった予測には結果がなく、数えません。
## 表と計画
`progress.table_of` は、受理された `end` スナップショットの表（確認済み）、なければ行のある最後のスナップショットの表（未確認）、それもなければ表なしを採ります。計画の行は、そのスナップショットの `tasks.md` の `- [x]`/`- [ ]` の行で、記録どおりの書き手がつきます。状態の数は、ベンチの 4 つの語だけを数えます。
## 夜と昼
初期の色は夜の実験室です。`html[data-mode="day"]` がカスタムプロパティを置き換えます。スクリプトがその属性を設定し、`localStorage` に 1 つの値 `notebook-mode` を保存します。保存がブロックされていれば、選択はそのページの間だけです。付箋、写真、開いたメモは、どちらのモードでも紙の色を保ち、自分のインクの色を設定します。
## 撮り直した表示用の絵（要件 6）
フォルダーには `manifest.toml` と PNG のシートがあります。各 `[[retake]]` は `application`、`session`、`trial`、`file`、`sha256`、`source_picture`、`columns`、`rows`、`interval`、`frame_seconds`、`track`、`track_step`、`measured` を持ちます。次のどれかが満たされないと、ビルドはその項目を拒みます: ファイルの SHA-256 が `sha256` と同じ、`source_picture` がその試行の記録の絵のハッシュ、シートが `columns` と `rows` に隙間 0 で割り切れる、`measured` が空でなく、すべての値がその名前の記録の値と有効数字 4 桁で等しい、`track` が `track_step * columns * rows + 1` 個のサンプルを持つ記録のメートルの系列。絵は `p/<sha256>.png` としてコピーされ、拡大した絵の代わりに出ます。記録の全体のシートは「whole picture」のボタンで見られます。
### 絵の撮り方（`notebook-retake`、Mac で）
`uv run notebook-retake --sessions sessions --out notebook/display --session body-1 --session body-2`
1. 封印された記録は読むだけで書かない。出力のフォルダーは新しいか空。
2. 各試行について、記録された命令（`trial.inputs`）を body-lab のアダプター自身のシミュレーター（`sim.run`。シミュレーションに乱数はなく、シードは試行とともに記録されている）でもう一度走らせ、アダプター自身のメジャラーで x、y、heading と 3 本の track を計算し、記録と厳密に比べる。1 つでも違えば、試行と測定の名前を言って止まる。2026-11-19 に body-1 と body-2 の全 79 試行が一致した。
3. 同じ走りの中で、シミュレーション時間の 0.2 秒ごとに 25 枚、1 辺 320px で描く。レンダラーの自由カメラが体の重心の真上から見るので、床は 50cm 幅に見え、体の後ろで市松模様が動く。アダプターも、そのカメラも、実験装置が返す絵も変えない。
4. 25 枚を隙間 0 で 5×5 に並べる。各色の下位 3 ビットを落とし、各行を一番小さくなる PNG フィルターで保存するので、1 シートは約 0.3MB（79 枚で 20MB）。このシートは表示用の絵で、測定ではない。
5. シートの SHA-256、記録の絵のハッシュ、レイアウト、測定値を `manifest.toml` に書く。
風洞は走らせ直さない: 大きい絵にはソルバーのサンプリングを変える必要があり（`wind-tunnel/model`、`wind-tunnel` の spec の変更）、ここでは触らない。風洞の絵は記録のものを切り抜いて出す（`zoom.py`）: スクリプトは各コマの、体と渦のまわりの窓だけを描く（最初のコマの体の灰色から見つける）。全体の絵はボタン 1 つで出る。
## ページの上の部分
ページの上の数字は短い（`numbers.brief`）: 10cm 未満のメートルはセンチメートル（`+3.9 cm`）、それ以上はメートル（`0.75 m`）、単位のない値は小数 3 桁（`0.993`）で、e の表記はなし。記録の値は開いたメモに出す。見どころの 2 枚の写真は 1 つのグループで、1 つの再生ボタンと 1 本のつまみが両方を動かし、各写真の下に、そのコマの記録の track から「t = 3.0 s forward 38 cm」の行を出す。グラフは枠で囲み、名前を付けるのは大きい段（伸びの 10% 以上）の多くて 4 つで、名前どうしが重ならない場所に置く。題はクリーム色で、人が書いた文は普通の字に小さなオレンジの印「our notes」。発見した spec のカードは id、判子、規則、書き直しを見せ、範囲と根拠は閉じたメモに入れる。計画の各段は 1 行で、押すと全文が開く。各仮説は 2 列のカードで、メモを開くと 2 列にまたがる。
## Decisions
1. 行の判子は、その実験を引く表の行の状態（ベンチの 4 つの語）。Dr. Kiro の判定の語（supported、partly、rejected）は別の語で、開いたメモの中に Dr. Kiro のインクで出す。
2. 最初に数えられた試行は、前に何もないので、「ここまでの一番」でも仮説の行でも「new best」にしない。
3. モデル名は記録にない。choices のファイルの必須のキーで、人が書く。
4. 日付は、人が言うセッションの封印の日。記録に時刻はない。最初の日付は、各記録が git に入った日。
